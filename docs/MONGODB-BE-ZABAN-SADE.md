# MongoDB به زبان خیلی ساده

> این فایل را برای خودم نوشتم تا هر وقت یادم رفت، دوباره بخوانمش.
> هیچ پیش‌نیازی ندارد؛ فرض شده هیچ‌وقت با دیتابیس کار نکرده‌ای.

---

## ۱) دیتابیس یعنی چه؟

دیتابیس یک **کمد بایگانی** است که برنامه اطلاعاتش را آنجا نگه می‌دارد تا بعداً پیدایشان کند.
بدون دیتابیس، هر بار که سرور را خاموش کنی همه‌چیز پاک می‌شود (مثل نوشتن روی تخته‌وایت‌برد و بعد پاک کردنش).

در پروژه ما این اطلاعات در دیتابیس است:

- فروشگاه‌ها و کاربرها (کی مالک است، کی صندوق‌دار)
- محصولات، دسته‌بندی‌ها، بارکدها
- فاکتورها، پرداخت‌ها، مشتری‌ها
- هزینه‌ها و سند‌های حسابداری (دفتر کل)
- رویدادهای اسکن بارکد

---

## ۲) MongoDB چه فرقی با دیتابیس‌های قدیمی (SQL) دارد؟

دو خانواده دیتابیس وجود دارد:

| | **SQL** (مثل PostgreSQL، MySQL) | **MongoDB** (خانواده NoSQL) |
|---|---|---|
| اطلاعات چطور ذخیره می‌شود | در **جدول**، مثل اکسل: سطر و ستون | در **سند**، مثل یک فایل JSON |
| ساختار | ستون‌ها از قبل ثابت تعریف شده‌اند | هر سند می‌تواند شکل خودش را داشته باشد |
| اسم ظرف | Table (جدول) | **Collection** (مجموعه) |
| اسم یک رکورد | Row (سطر) | **Document** (سند) |
| ارتباط بین جدول‌ها | با `JOIN` | معمولاً با **نگه‌داشتن آیدی** (و خواندن در دو مرحله) |

### مثال تصویری

در SQL، یک محصول یک سطر از جدول `products` است:

```
id | name     | price  | stock
---+----------+--------+------
1  | شیر      | 18000  | 10
```

در MongoDB، همان محصول یک **سند** است (شبیه JSON):

```json
{
  "_id": ObjectId("6acc4d2f3f4df985ddbd4e01"),
  "storeId": "6acc4d2f3f4df985ddbd4e00",
  "name": "شیر کم‌چرب",
  "price": 18000,
  "stock": 10,
  "barcodes": ["6281111000019"],
  "createdAt": ISODate("2026-10-12T08:00:00Z")
}
```

چند نکته از همین مثال:

1. **`_id`** = کارت ملیِ هر سند. خودش خودکار ساخته می‌شود و در کل دنیا یکتاست.
   اگر خودت `_id` نگذاری، MongoDB یکی از نوع `ObjectId` برایت می‌سازد.
2. **`barcodes` یک آرایه است.** در SQL مجبور بودی یک جدول جدا (`product_barcodes`) بسازی؛
   در MongoDB همان‌جا داخل خود سند می‌گذاری. این یکی از بزرگ‌ترین راحتی‌های MongoDB است.
3. **`createdAt` از نوع تاریخ واقعی است**، نه متن. پس می‌شود رویش مقایسه انجام داد
   (مثلاً «فروش‌های بزرگ‌تر یا مساوی امروز»).

## ۳) چهار کلمه‌ای که باید بلد باشی

| کلمه | معنی ساده | مثال |
|---|---|---|
| **Database** | کل کمد بایگانی | `mystore` |
| **Collection** | یکی از قفسه‌های کمد | `products`، `invoices` |
| **Document** | یک برگه داخل قفسه | یک محصول مشخص |
| **Field** | یک خانه روی آن برگه | `price`، `stock` |

نکته مهم: **نیازی نیست از قبل قفسه بسازی.** اولین باری که یک سند داخل
`products` ذخیره کنی، خود `products` ساخته می‌شود. (در SQL باید اول `CREATE TABLE` می‌زدی.)

## ۴) کارهای اصلی با دیتابیس (CRUD)

هر برنامه فقط چهار کار با اطلاعات می‌کند:

| کار | معنی | دستور MongoDB |
|---|---|---|
| **C**reate | اضافه کردن | `insertOne` / `insertMany` |
| **R**ead | خواندن | `find` / `findOne` |
| **U**pdate | ویرایش | `updateOne` / `updateMany` |
| **D**elete | حذف | `deleteOne` / `deleteMany` |

### خواندن با «فیلتر»

`find` به یک **شرط** می‌گیرد که به آن **filter** می‌گوییم:

```js
// همه محصولاتی که موجودی‌شان زیر ۵ است
products.find({ stock: { $lt: 5 } })

// محصولاتی که اسمشان «شیر» است و در این فروشگاه‌اند
products.find({ storeId: "6acc...", name: "شیر" })

// هر چیزی که بارکدش این باشد
products.find({ barcodes: "6281111000019" })
```

علامت `$` یعنی «عملگر»:

| عملگر | معنی |
|---|---|
| `$lt` / `$lte` | کمتر از / کمتر یا مساوی |
| `$gt` / `$gte` | بیشتر از / بیشتر یا مساوی |
| `$ne` | مساوی نباشد |
| `$in` | عضو این لیست باشد |
| `$exists` | این فیلد وجود داشته باشد |
| `$regex` | جست‌وجوی متنی (مثل `LIKE` در SQL) |

### ویرایش با `$set` و `$inc`

```js
// قیمت را عوض کن
products.updateOne({ _id: id }, { $set: { price: 20000 } })

// موجودی را ۳ تا کم کن (بدون اینکه اول بخوانی و بعد بنویسی!)
products.updateOne({ _id: id }, { $inc: { stock: -3 } })
```

`$inc` خیلی به درد فروشگاه می‌خورد: وقتی فاکتور ثبت می‌شود، به‌جای
«بخوان، منهای ۳ کن، بنویس» فقط می‌گوییم «۳ تا کم کن». این‌طوری اگر دو نفر
همزمان خرید کنند، موجودی اشتباه نمی‌شود.

### مرتب‌سازی و صفحه‌بندی

```js
products
  .find({ storeId })
  .sort({ createdAt: -1 })   // 1 = صعودی، -1 = نزولی
  .skip(20)                  // از ردیف ۲۱ به بعد
  .limit(10)                 // فقط ۱۰ تا
```

## ۵) «آیدی» و رابطه بین سند‌ها (مهم‌ترین بخش)

در SQL می‌گویی «این فاکتور را بده، همراه با مشتری‌اش» و با یک `JOIN` همه‌چیز می‌آید.
در MongoDB **JOIN وجود ندارد** (دقیق‌تر: `$lookup` هست ولی گران و پرپیچیده است).
روش درست و ساده این است:

> **آیدی را نگه دار، بعداً جدا بخوان.**

یعنی سند فاکتور، کل مشتری را در خودش ندارد؛ فقط آیدی‌اش را دارد:

```json
{
  "_id": ObjectId("..."),
  "number": "INV-0001",
  "customerId": "6acc4d2f3f4df985ddbd4e30",   // ← فقط آیدی
  "storeId": "6acc4d2f3f4df985ddbd4e00",
  "items": [
    { "id": "a1b2...", "productId": "6acc4d2f3f4df985ddbd4e01", "name": "شیر", "qty": 2, "price": 18000 }
  ]
}
```

و در کد، **دو مرحله** می‌خوانیم:

```ts
const invoice = await invoices.findOne({ _id: id });                 // ۱) فاکتور
const customer = await customers.findOne({ _id: invoice.customerId }); // ۲) مشتری
```

در این پروژه این کار را یک‌جا جمع کرده‌ایم در تابع `attachInvoiceRelations`
(فایل `apps/web/src/lib/repositories.ts`) تا در صفحه‌ها تکرار نشود.

### استثنا: وقتی «جاسازی» (Embedding) بهتر است

اگر یک داده **همیشه** با والدش خوانده می‌شود و مستقل معنی ندارد،
به‌جای آیدی، همان‌جا داخل سند می‌گذاریم. در پروژه ما:

| داده | روش ما | چرا |
|---|---|---|
| `items` داخل فاکتور | **جاسازی** (داخل سند فاکتور) | آیتمِ فاکتور بدون فاکتور معنی ندارد؛ همیشه با هم خوانده می‌شوند |
| `payments` داخل فاکتور | **جاسازی** | همان دلیل |
| `barcodes` روی محصول | **جاسازی** | لیست کوتاهی است |
| مشتریِ فاکتور | **آیدی** | مشتری مستقل است، صفحه و گزارش جدا دارد |
| محصولِ آیتم | **آیدی** | محصول مستقل است، قیمتش عوض می‌شود و نباید در فاکتورهای قدیمی تغییر کند |

قاعده سرانگشتی: **اگر تنها می‌شود رویش جست‌وجو کرد یا ویرایشش کرد → آیدی. اگر همیشه چسبیده به والدش است → جاسازی.**

> ⚠️ **یک نکته ظریف که یک روز کامل ما را معطل کرد:**
> در پروژه ما همه `_id`های سطح بالا از نوع `ObjectId` هستند، اما **همه آیدی‌های
> مرجع (`storeId`، `customerId`، `productId`، …) و `_id` آیتم‌های جاسازی‌شده
> به صورت رشته‌ی هگز ۲۴ کاراکتری** ذخیره می‌شوند.
> دلیلش فنی است (سازگاری با سرور توسعه‌ی `easydb` که `ObjectId`های غیر `_id` را
> خراب برمی‌گرداند) ولی فایده‌اش هم این است که JSON خروجی API مستقیماً قابل
> استفاده است و نیازی به تبدیل نیست.
> **قانون طلایی:** وقتی می‌خواهی با آیدی چیزی را پیدا کنی، از هلپرهای
> `oid()` / `oidOrNull()` در `apps/web/src/lib/db.ts` استفاده کن، نه مقدار خام.

## ۶) ایندکس (Index) = فهرست کتاب

اگر ۱۰۰٬۰۰۰ محصول داشته باشی و `find({ storeId })` بزنی، بدون ایندکس MongoDB
**همه را یکی‌یکی نگاه می‌کند** (اسکن کامل) → کند می‌شود.

ایندکس مثل **فهرست آخر کتاب** است: یک ساختار مرتب که سریع پیدایت می‌کند.

```js
await products.createIndex({ storeId: 1, name: 1 });
```

قاعده: **روی فیلدهایی که در شرط‌های `find` زیاد استفاده می‌شوند ایندکس بزن.**
در این پروژه ایندکس‌ها در `apps/web/src/lib/db.ts` (تابع `ensureIndexes`) ساخته می‌شوند.
زیاده‌روی نکن: هر ایندکس نوشتن را کمی کند می‌کند و جا می‌گیرد.

## ۷) Aggregate = ماشین‌حساب گزارش‌ها

`find` فقط سند برمی‌گرداند. ولی برای گزارش («جمع فروش امروز چقدر بود؟»)
به **محاسبه** نیاز داریم. این کار با **Pipeline** انجام می‌شود: یک لوله که سند‌ها
از آن رد می‌شوند و مرحله‌به‌مرحله تغییر می‌کنند.

```js
invoices.aggregate([
  { $match: { storeId, status: "PAID" } },          // ۱) فیلتر کن
  { $unwind: "$items" },                             // ۲) هر فاکتور را به چند ردیف آیتم بشکن
  { $group: {                                          // ۳) دسته‌بندی و جمع کن
      _id: null,
      total: { $sum: { $multiply: ["$items.qty", "$items.price"] } },
  }},
  { $sort: { total: -1 } },                          // ۴) مرتب کن
  { $limit: 10 },                                    // ۵) فقط ۱۰ تا
]);
```

مراحل پرکاربرد: `$match` (فیلتر)، `$group` (گروه‌بندی + جمع)، `$unwind` (باز کردن آرایه)،
`$sort`، `$limit`، `$project` (انتخاب فیلدها).

همه‌ی ریاضیات گزارش‌های این پروژه در یک فایل جمع شده: **`apps/web/src/lib/stats.ts`**
تا هم API و هم صفحه‌ها یک عدد را نشان دهند.

## ۸) تراکنش (Transaction) — و یک هشدار مهم برای پروژه ما

در کارهای پولی گاهی لازم است **چند نوشتن با هم موفق شوند یا هیچ‌کدام**:
ثبت فاکتور = نوشتن فاکتور + کم کردن موجودی + نوشتن سند حسابداری + به‌روزرسانی بدهی مشتری.
اگر وسطش برق برود، حساب‌ها به هم می‌ریزد. به این می‌گویند **تراکنش**.

در این پروژه همه‌ی این جریان‌ها از تابع `runInTransaction` در `apps/web/src/lib/db.ts` رد می‌شوند.

> ⚠️ سرور توسعه‌ی ما (`easydb-server` با `--adapter memory`) تراکنش **پشتیبانی نمی‌کند**.
> به همین دلیل `runInTransaction` طوری نوشته شده که اگر تراکنش در دسترس نبود،
> همان نوشتن‌ها را **به‌ترتیب و پشت‌سرهم** انجام دهد (بدون تضمین بازگشت).
> روی MongoDB واقعی (replica set) همان کد **بدون تغییر** از تراکنش واقعی استفاده می‌کند.
> با متغیر محیطی `MONGODB_TRANSACTIONS=on|off|auto` هم می‌شود دستی کنترلش کرد.

## ۹) چطور پروژه را با MongoDB بالا بیاوریم؟

سه راه داری، از ساده به حرفه‌ای:

### الف) سرور تمرینی داخل همین ریپو (بدون نصب چیزی) ← برای توسعه روزمره

```bash
pnpm db:sandbox     # یک MongoDB-سازگار در 127.0.0.1:27017 بالا می‌آورد (داده در حافظه)
pnpm db:seed        # داده‌ی نمونه می‌ریزد
pnpm dev            # وب‌اپ
```

داده‌ی این سرور **در حافظه است**؛ با خاموش کردنش پاک می‌شود. برای یادگیری و تست عالی است.

### ب) Docker (MongoDB واقعی) ← اگر Docker داری

```bash
pnpm docker:up      # mongo:8 روی پورت 27017 با حجم ماندگار
pnpm db:seed
pnpm dev
```

### ج) MongoDB Atlas (ابری، رایگان) ← برای استقرار

یک کلاستر رایگان M0 در <https://cloud.mongodb.com> بساز،
IP خودت را whitelist کن، و `MONGODB_URI` را در `.env.local` بگذار.

### متغیرهای محیطی (`apps/web/.env.local`)

```env
MONGODB_URI=mongodb://127.0.0.1:27017/mystore?directConnection=true
MONGODB_DB=mystore
AUTH_SECRET=یک-رشته-تصادفی-بلند
AUTH_TRUST_HOST=true
# اختیاری:
MONGODB_TRANSACTIONS=auto
MONGODB_MAX_POOL_SIZE=10
REDIS_URL=            # فقط اگر صف Realtime لازم شد
```

> `directConnection=true` برای وقتی است که به یک سرور تک‌گره وصل می‌شوی؛
> بدون آن، درایور دنبال replica set می‌گردد و ممکن است معطل شود.

### حساب‌های نمونه (بعد از `pnpm db:seed`)

| ایمیل | رمز | نقش |
|---|---|---|
| `owner@mystore.ir` | `123456` | OWNER (دسترسی کامل) |
| `cashier@mystore.ir` | `123456` | CASHIER (فقط صندوق) |

## ۱۰) ساختار کد دیتابیس در این پروژه

| فایل | کار |
|---|---|
| `apps/web/src/lib/db.ts` | اتصال به Mongo، هلپرهای `oid()`، ایندکس‌ها، `runInTransaction` |
| `apps/web/src/lib/models.ts` | شکل سند‌ها در TypeScript (`ProductDoc`, `InvoiceDoc`, …) |
| `apps/web/src/lib/repositories.ts` | توابع خواندن/نوشتن + وصل‌کردن روابط (`attachInvoiceRelations`) |
| `apps/web/src/lib/serialize.ts` | تبدیل سند خام → DTO تمیز برای API و صفحه‌ها |
| `apps/web/src/lib/stats.ts` | همه‌ی aggregateها و ریاضی گزارش‌ها |
| `apps/web/src/lib/ledger.ts` | سند‌های حسابداری (بدهکار/بستانکار) |
| `apps/web/src/lib/invoice-service.ts` | منطق فاکتور: صدور، پرداخت، لغو، موجودی |
| `apps/web/src/lib/scan-service.ts` | منطق اسکن بارکد |
| `apps/web/scripts/seed.mjs` | ریختن داده نمونه (`--fresh` = پاک کن و از نو، `--optional` = فقط اگر خالی بود) |

**کجا چیز جدید اضافه کنم؟**

- یک نوع داده جدید → سندش در `models.ts`، ایندکسش در `db.ts`
- خواندن/نوشتنش → `repositories.ts`
- تبدیلش به JSON → `serialize.ts`
- محاسبه/گزارش → `stats.ts`
- منطق کسب‌وکار (اگر/آنگاه‌های پولی) → یک سرویس مثل `invoice-service.ts`

## ۱۱) مقایسه سریع SQL ↔ MongoDB (تقلب)

| SQL | MongoDB |
|---|---|
| `CREATE TABLE products (...)` | لازم نیست؛ اولین `insertOne` خودش collection را می‌سازد |
| `SELECT * FROM products` | `products.find({})` |
| `SELECT * FROM products WHERE id = 5` | `products.findOne({ _id: oid("...") })` |
| `WHERE price > 100` | `{ price: { $gt: 100 } }` |
| `WHERE name LIKE '%شیر%'` | `{ name: { $regex: "شیر" } }` |
| `WHERE store_id = 1 OR cat_id = 2` | `{ $or: [{ storeId: 1 }, { categoryId: 2 }] }` |
| `INSERT INTO ...` | `insertOne(...)` |
| `UPDATE products SET price = 9 WHERE id = 5` | `updateOne({ _id: ... }, { $set: { price: 9 } })` |
| `DELETE FROM products WHERE id = 5` | `deleteOne({ _id: ... })` |
| `COUNT(*)` | `countDocuments({})` |
| `ORDER BY created_at DESC LIMIT 10` | `.sort({ createdAt: -1 }).limit(10)` |
| `GROUP BY ... SUM(...)` | `aggregate([{ $group: { _id: ..., total: { $sum: ... } } }])` |
| `JOIN` | آیدی را نگه دار و در یک کوئری دوم بخوان |
| `BEGIN; ... COMMIT;` | `runInTransaction(async (session) => { ... })` |

## ۱۲) اشتباه‌هایی که تازه‌کارها می‌کنند

1. **آیدی را با رشته مقایسه کردن.** `_id` از نوع `ObjectId` است؛
   `findOne({ _id: "6acc..." })` روی سرور واقعی کار می‌کند ولی قابل اتکا نیست.
   همیشه `oid(id)` بزن.
2. **فراموش کردن `storeId` در کوئری‌ها.** این برنامه **چندفروشگاهی** است؛
   هر کوئری باید `storeId` داشته باشد وگرنه داده‌ی یک فروشگاه به دیگری نشت می‌کند.
3. **`updateOne` بدون شرط.** اگر فیلتر خالی `{}` بدهی، همه‌ی سند‌ها عوض می‌شوند.
4. **جاسازی بی‌حد.** اگر آرایه‌ی `items` را بی‌نهایت بزرگ کنی، سند سنگین می‌شود
   (سقف MongoDB حدود ۱۶ مگابایت برای هر سند است). برای فاکتور مشکلی نیست.
5. **ایندکس نزدن** روی فیلدهای پرجست‌وجو → در داده‌ی زیاد، برنامه کند می‌شود.
6. **تکیه کردن به `unique` در دیتابیسِ تمرینی.** `easydb-server` یکتایی را
   enforce نمی‌کند؛ به همین دلیل یکتایی بارکد را در کد چک می‌کنیم و `409` برمی‌گردانیم.
7. **`$facet` در سرور تمرینی کار نمی‌کند.** ما در `stats.ts` عمداً استفاده نمی‌کنیم؛
   چند aggregate ساده می‌زنیم. (روی MongoDB واقعی هر دو کار می‌کند.)

---

## ۱۳) خلاصه‌ی ۳۰ ثانیه‌ای

> MongoDB اطلاعات را مثل **JSON** نگه می‌دارد، نه مثل جدول اکسل.
> هر ظرف یک **collection** است و هر رکورد یک **document** با یک `_id` یکتا.
> رابطه‌ها را با **نگه‌داشتن آیدی** می‌سازیم و در دو مرحله می‌خوانیم؛
> چیزهایی که همیشه به والدشان چسبیده‌اند (مثل آیتم‌های فاکتور) را **داخل همان سند** می‌گذاریم.
> برای گزارش از **aggregate** و برای سرعت از **index** استفاده می‌کنیم.
> نوشتن‌های پولی را داخل **تراکنش** می‌گذاریم.
